# Priority 2 — বট শিল্ড (Turnstile) + API রেট লিমিটিং

লক্ষ্য: ফেক অর্ডার, স্প্যাম সাইনআপ, পাসওয়ার্ড অনুমান করার চেষ্টা এবং AI চ্যাট অপব্যবহার — এই চারটি বন্ধ করা, আসল গ্রাহকের কোনো বাড়তি ঝামেলা ছাড়াই।

## ১) রেট লিমিটিং (সবার আগে)

প্রতিটি পাবলিক অনুরোধ গোনা হবে — একই IP বা একই ফোন নম্বর থেকে অল্প সময়ে অস্বাভাবিক বেশি অনুরোধ এলে সাময়িকভাবে থামিয়ে দেওয়া হবে (HTTP 429, বাংলা বার্তাসহ)।

শুরুতে যেসব জায়গায় বসবে:

| জায়গা | সীমা |
| --- | --- |
| ল্যান্ডিং পেজ অর্ডার + ল্যান্ডিং কানেকশন অর্ডার | প্রতি IP ১০ / ১০ মিনিট |
| স্টোর চেকআউট / কুইক অর্ডার | প্রতি IP ১৫ / ১০ মিনিট |
| গ্রাহক ও মার্চেন্ট লগইন/সাইনআপ/কোড পাঠানো | প্রতি IP ১০ / ১৫ মিনিট |
| স্টোরফ্রন্ট AI চ্যাট | প্রতি IP ৩০ / ১০ মিনিট |
| কন্টাক্ট / নিউজলেটার | প্রতি IP ৫ / ১০ মিনিট |

নিয়মগুলো এক জায়গায় থাকবে, পরে যেকোনো সময় বাড়ানো-কমানো যাবে। আপনার নিজের অ্যাডমিন প্যানেল, cron এবং যাচাই করা ওয়েবহুক (Facebook, পেমেন্ট গেটওয়ে) এর বাইরে থাকবে — ওগুলো আগে থেকেই সাইন-করা।

## ২) Turnstile বট শিল্ড

Cloudflare Turnstile — ক্যাপচার মতো, কিন্তু বেশিরভাগ সময় গ্রাহককে কিছুই করতে হয় না (অদৃশ্য যাচাই)। বসবে: ল্যান্ডিং পেজ অর্ডার ফর্ম, স্টোর চেকআউট, গ্রাহক সাইনআপ ও লগইন, পাসওয়ার্ড রিসেট কোড, কন্টাক্ট ফর্ম।

সার্ভারে টোকেন যাচাই না হলে অনুরোধ বাতিল। কি না থাকলে সিস্টেম নিজে থেকে যাচাই বন্ধ রাখবে (ফর্ম ভাঙবে না) — তাই ধাপে ধাপে চালু করা নিরাপদ।

চাবি সংগ্রহ: আমি Cloudflare API দিয়ে `orzen.top`-এর জন্য উইজেটটি নিজে তৈরি করার চেষ্টা করব। টোকেনের অনুমতি না থাকলে আপনাকে জানাব এবং একটি নিরাপদ ফর্ম খুলে দেব — শুধু দুটি চাবি পেস্ট করবেন, আর কিছু করতে হবে না।

## ৩) অপব্যবহার নজরদারি

বারবার আটকে যাওয়া IP গুলো লগে জমা থাকবে; অ্যাডমিন প্যানেলের নিরাপত্তা পাতায় "গত ২৪ ঘণ্টায় ব্লক হওয়া অনুরোধ" দেখা যাবে।

## যাচাই ও ডিপ্লয়

- লোকালে: সীমার বেশি অনুরোধ পাঠিয়ে 429 আসছে কিনা দেখা হবে; স্বাভাবিক একটি অর্ডার আগের মতোই কাজ করছে কিনা দেখা হবে।
- এরপর `scripts/deploy-production.sh` দিয়ে লাইভে; লাইভে আসল ফর্মে একটি অর্ডার দিয়ে Playwright-এ যাচাই করে তবেই "হয়ে গেছে" বলব।

## টেকনিক্যাল সারাংশ

- নতুন `src/lib/rate-limit.server.ts` — Postgres-ভিত্তিক ফিক্সড-উইন্ডো কাউন্টার (`public.rate_limit_hits` টেবিল + `rate_limit_hit(_key, _limit, _window_sec)` SECURITY DEFINER RPC, অ্যাটমিক upsert; সার্ভিস-রোল দিয়ে কল, কোনো anon grant নেই)। ক্লায়েন্ট IP = `CF-Connecting-IP` → `x-forwarded-for` প্রথম অংশ।
- মাইগ্রেশনে টেবিল + GRANT (`service_role` only) + RLS enable + পুরনো সারি মুছে ফেলার জন্য cron-এ যুক্ত হবে এমন ক্লিনআপ ফাংশন।
- নতুন `src/lib/turnstile.server.ts` — `siteverify` কল, `TURNSTILE_SECRET_KEY` না থাকলে `{ ok: true, skipped: true }`; ক্লায়েন্টে `src/components/TurnstileWidget.tsx` (স্ক্রিপ্ট lazy-load, `VITE_TURNSTILE_SITE_KEY` না থাকলে কিছুই রেন্ডার করে না)।
- সংযুক্ত হবে: `src/routes/api/public/lp.order.ts`, `src/routes/api/public/landing-pages/$connectionId/*.ts` (embed পথে), `src/routes/api/ai/chat.ts`, `src/lib/customer-auth.functions.ts`, `src/lib/merchant-security.functions.ts` (issueCode-এর আগে), `src/lib/quick-order.server.ts`, `src/lib/newsletter.functions.ts`।
- HMAC-যাচাই করা ওয়েবহুক ও `CRON_SECRET` পথগুলো বাদ থাকবে।
